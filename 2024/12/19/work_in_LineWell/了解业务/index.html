基本业务结构:

业务流程:

  1. autogenerator

    • 包含controller、entity、mapper、service等。
    • 这个目录通常是由代码生成器生成的基础代码，如实体类（entity）、数据库映射层（mapper）、服务层接口（service），以及部分Controller代码。
    • 用途： 提供基础的CRUD逻辑，与底层数据库表结构直接对应。

  2. bll（业务逻辑层）

    • 职责： 实现具体的业务逻辑处理，主要对service层提供的基础方法进行封装或组合，完成实际的业务需求。
    • 判断： 如果代码中存在复杂的业务流程，比如订单处理、库存管理等，它们的核心逻辑应当位于bll层。

  3. constants（常量层）

    • 职责： 定义项目中的常量、枚举等，如错误码、业务类型标识符等。
    • 判断： 如果有需要统一管理的常量信息，放在这里符合约定。常量可以在bll、controller、facade层等各层使用。

  4. dto（数据传输层）

    • 职责： 用于封装与前端交互的数据结构，一般是传输用的Java对象，或者用于返回结果的封装。
    • 判断： 通常用于Controller层和Facade层之间，或用作外部服务的输入输出对象。

  5. facade（门面层）

    • 职责： 对外提供统一的接口，用于聚合调用多个业务逻辑（可能包括多个bll层的逻辑），实现复杂的场景处理。
    • 判断： 如果某些功能需要组合多个bll层的功能逻辑或调用其他微服务，这部分逻辑可以放在facade层。

  6. params（参数层）

    • 职责： 专门用于接收和校验请求参数的层。

    • 判断：

      主要包含

      类的子集，通常在Controller层中使用，结合Spring Validation进行参数验证。

      • 如果请求参数数量多，或者需要复杂校验，适合放在params层。
      • 例如：表单参数校验、分页参数、筛选条件等。

  7. util（工具层）

    • 职责： 封装项目中可能会重复使用的工具类（如日期格式化、加解密、字符串处理等）。
    • 判断： 仅包含纯粹的工具类代码，与具体业务无关。

MyBatis-Plus的批量读取的操作,但是目标的SQL其实还是一条一条的插入

在java的JDBC下可以设置这个参数,rewriteBatchedStatements=true ,使其可以将多个SQL语句合并为一个SQL语句

速度非常快

rewriteBatchedStatements=true 的魔力

  • 启用批处理重写：启用批处理重写功能后，驱动能够将多条同类型的 SQL 语句进行合并，进而发送给数据库执行。

  • 减少网络交互：一次发送多条 SQL，可有效降低网络延迟，减少网络交互次数。

  • 提高执行效率：当所有数据都通过一条 SQL 插入时，MySQL 只需要解析一次 SQL，降低了解析和执行的开销。

  • 减少内存消耗：虽然批量操作时将数据合并到一条 SQL 中，理论上会增加内存使用（因为需要构建更大的 SQL 字符串），但相比多次单条插入的网络延迟和处理开销，整体的资源消耗和执行效率是更优的。

JDBC 批处理机制

JDBC 批处理机制是一种优化数据库操作性能的技术，允许将多条 SQL 语句作为一个批次发送到数据库服务器执行，从而减少客户端与数据库之间的交互次数，显著提高性能。通常用于 批量插入、批量更新 和 批量删除 等场景。具体的流程如下：

2、MySQL JDBC 驱动的默认行为对批处理的影响

  • 未开启重写：在默认状态下，MySQL JDBC 驱动会逐一条目地发送批处理中的 SQL 语句，未开启重写功能。

  • 性能瓶颈：频繁的网络交互以及数据库解析操作，使得批量操作的性能提升效果有限，形成了性能瓶颈。

3、rewriteBatchedStatements=true 的魔力

  • 启用批处理重写：启用批处理重写功能后，驱动能够将多条同类型的 SQL 语句进行合并，进而发送给数据库执行。

  • 减少网络交互：一次发送多条 SQL，可有效降低网络延迟，减少网络交互次数。

  • 提高执行效率：当所有数据都通过一条 SQL 插入时，MySQL 只需要解析一次 SQL，降低了解析和执行的开销。
